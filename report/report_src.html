2Motivation

Who has the problem. First-time and young voters, students in civics classes, and casual followers who want to know "is my race close, and who's running?" The people I built this around are my classmates: smart, busy, and not going to read eight forecasting sites.

How they handle it today. To answer "who's favored in the Texas Senate race?" you have to visit Cook Political Report, Inside Elections, Sabato's Crystal Ball, The Economist, Split Ticket, Decision Desk HQ, FiftyPlusOne, Fox News, Silver Bulletin and RealClearPolitics separately. Several are paywalled or bury race pages; each uses its own wording (Tilt, Lean, Likely, Safe), and none tells you which races are on your ballot or how to register. Then candidates' names, parties and websites are on yet another site (Ballotpedia).

What that costs. For one race, checking ten outlets takes roughly 10 to 15 minutes (my own timing, opening each site and finding the race). Doing that for your Senate, governor and House race is 30 to 45 minutes, and most people simply don't, so they vote with less information or don't engage at all. Youth turnout in midterms has historically been far below older voters'.

Where newcomers get stuck. Even with every race in one place, a first-time voter doesn't know which of 506 races to look at, why a state has four candidates, or what "Tilt R" means. So the site opens with a short explainer and a "Races to Watch" list instead of dropping people into the full data.

Why anyone should care. Midterms decide control of Congress and 36 governorships, yet attention is low. A tool that is fun (mascots, a prediction game, a leaderboard) and fast (every forecaster in one glance) lowers the cost of being an informed voter.

The kid-friendly design (party-mascot avatars that look like the candidates, flying eagles) is deliberate: the audience is new voters.

4The agents

"Ask Joey" is a five-part pipeline: three model agents and two code agents. Two more code layers sit around them (a safety screen and an output filter). A separate Results agent runs on election night.

Figure: who hands work to whom. Yellow = code (can't be talked out of its rules), blue = model agents (gpt-6-luna), green = the only data agents can read.

PartTypeWhat it doesTools / access
Safety screencodeBlocks prompt injection, data-theft and script attempts before any model is callednone
Routermodel, structured outputDecides intent (race, state, compare, how-it-works, off-topic) and which race ids the question is about. Off-topic questions stop here.none
Researchermodel + toolsLooks up the facts for those races and writes a short fact summaryget_race, list_races: read-only race data
Analyst "Joey"model, no toolsWrites a friendly answer (under 120 words) using only the factsnone
VerifiercodeEvery number in the answer must appear in what the Researcher's tools returned. One retry with feedback, then a safe answer built straight from the data.reads the tool results
Output filtercodeBlocks anything that looks like a password hash, API key, token or emailnone
Results agentmodel, election nightReads a results page and suggests winners with a quoted sentence. Code checks the race, the candidate and that the quote is really on the page; a person approves each one in approve.py.none; can't write results

Why this organization

  • Separate jobs = smaller prompts and cheaper calls. The Router is ~300 tokens and stops off-topic questions early; only race questions pay for research.
  • Code for anything that must be exactly right. Checking numbers and blocking secrets are rules, not judgment, so they're code: free, instant and impossible to sweet-talk.
  • Least privilege. No agent has a tool that touches the accounts table. Even a fully hijacked agent has nothing to steal.

Model

gpt-6-luna through Portkey with PydanticAI (the course key's required model). I made one tiny test call to confirm the key accepts it (13 input / 5 output tokens). A small, fast model fits: every answer is short and grounded in supplied facts, and the code Verifier catches the main failure mode (made-up numbers).

One real run, step by step

Question typed into the live app: "Who is favored in the Maine Senate race, and what is Joey's call?"

  1. Safety screen: passes (a normal question).
  2. Router (1 request): intent race, race id sen-me.
  3. Researcher (2 requests, 1 tool call): calls get_race("sen-me"), which returns candidates (Troy Jackson D, Susan Collins R), ten outlet ratings, consensus "Tilt D", model D 72% / R 28%, Joey's call R. It summarizes.
  4. Analyst "Joey" (1 request) writes the answer.
  5. Verifier: every number checks out on the first try. Output filter: ok.
{{IMG:05_ask_joey_run|The real run in the app. "How Joey answered" shows each agent's step (Router → sen-me, Researcher 1 tool call, Verifier: every number checks out, Output filter ok).}}

Across the 10 answered questions in my evidence run, the Verifier passed every answer on the first attempt; its retry path and fallback are covered by tests (it flags "73%" when the facts say 58).

8Limits and next steps

  • Ratings are a snapshot (Aug 11 to Oct 22, 2026, last refreshed Oct 24), entered from public pages. Next: a scheduled refresh agent that proposes rating changes for human approval, like the Results agent.
  • Few individual polls. Only one verified poll is loaded. Next: a polling feed with sample sizes and dates.
  • The model is experimental and mostly echoes the forecasters; it hasn't been back-tested. Next: back-test on 2018 to 2024 results.
  • Look-alike props are done for about 250 candidates; lesser-known nominees are plain mascots, on purpose, to avoid wrong details. Next: use official public-domain portraits to add hair and glasses only, verified per person.
  • Endorsement lists may be incomplete. A candidate shows an endorsement only if a source I could read named it, and one entry (Musk for Martin O'Donnell) rests on an X post supplied by me that automated tools couldn't open. Next: refresh the lists weekly, the same way.
  • The news filter is keyword-based, so an occasional off-topic or national story slips through. Next: use the Router agent to classify borderline headlines.
  • The shared game needs the server running. The public GitHub Pages demo keeps picks in each visitor's own browser. Next: host the backend so friends can play from their phones.
  • Prompt caching isn't used because prompts are short; at larger scale I'd move the race index into a cached system prompt.
